# 参考文献メーカー

ウェブページの情報を入力すると、**SIST 02-2007「参照文献の書き方」**の形式で参考文献を整形する静的サイトです。
足りない項目や URL の誤りを結果のすぐ下に書き出すので、提出前の確認に使えます。

- 公開先: <https://grossular31415.github.io/Sanko-Bunken-maker/>
- 入力内容はブラウザの中だけで処理され、どこにも送信・保存されません。
- 個人が作成した**非公式**のツールです。科学技術振興機構（JST）および SIST とは関係ありません。

## 対応している範囲

フェーズ1として、**ウェブページ1件**の整形に対応しています。

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 著者名または組織名 | 任意 | カンマ区切りで複数可。無い場合はタイトルから書き始める |
| ページのタイトル | 任意 | |
| サイト名 | 任意 | |
| 更新日 | 任意 | 不明なら省略。自由記述を受け付ける |
| URL | 任意 | http / https のみ有効 |
| 参照日 | 任意 | 初期値は今日 |

いずれも未入力でも整形結果は出力し、警告を添えます。**警告が出ていてもコピーできます。**

## 整形の根拠

SIST 02-2007 の「5.10 ウェブサイト, ウェブページ, ブログ」に従い、次の順に並べます。

```
著者名. “ページのタイトル”. サイト名. 更新日. URL, (参照 年-月-日).
```

| 判断 | 根拠にした節 |
| --- | --- |
| 書誌要素の並び順 | 5.10 書式および例1〜例3 |
| 著者が不明なら標題から書き始める | 4.1.3、5.10 例2 |
| 更新日が無ければ要素ごと省く | 5.10 例2 |
| 日付は `2000-02-02` 形式 | 4.3.4(4)(b) |
| 参照日は `(参照 1999-12-31)` 形式 | 4.4.5 例1 |
| 和文の連名は全角カンマ `，` | 4.1.1(3)(a) 例1「島田俊夫，平木敬，西田健次」 |
| 欧文の連名は半角セミコロン `; ` | 4.1.1(3)(a) 例2「Folland, Gerald B.; Stein, Elias M.」 |
| 3名を超える場合は「ほか」「et al.」で省略可 | 4.1.1(3)(b) |

### 区切り記号を半角にした理由

原文には表記のゆれがあります。**書式の表記**は全角ピリオド `．` と全角カンマ `，` ですが、
**掲載されている用例**は和文・欧文ともすべて半角ピリオド＋半角空白、半角カンマ＋半角空白です。

```
5.10 書式: 著者名．“ウェブページの題名”．ウェブサイトの名称．更新日付．…
5.10 例1 : 坂本和夫編. “パルスレーザー…の作製技術”. J-STORE. 2005-11-01. http://…, (参照 2006-06-23).
```

実際の参照文献リストに書く形を優先し、**用例に合わせて半角**を採用しました。
変更する場合は `src/format.js` の `ELEMENT_SEPARATOR` を書き換えてください。

原文は国立国会図書館のインターネット資料収集保存事業（WARP）に保存されています。

- [SIST 02-2007（HTML版）](https://warp.ndl.go.jp/web/20220119000000/jipsti.jst.go.jp/sist/handbook/sist02_2007/main.htm)
- [SIST 02-2007（PDF版）](https://warp.ndl.go.jp/web/20220119000000/jipsti.jst.go.jp/sist/pdf/SIST02-2007.pdf)

## ファイル構成

```
index.html          画面
styles.css          配色と余白
src/format.js       整形処理（UI に依存しない純粋関数のみ）
src/app.js          画面の組み立てと入出力
test/format.test.js node --test 用のテスト
```

整形の規則は `src/format.js` にだけ書きます。`src/app.js` には持ち込まないでください。

ビルドは不要です。外部ライブラリ・外部フォント・CDN は一切読み込みません。

## ローカルでの確認方法

Node.js 18 以上（22 で確認済み）が必要です。依存パッケージはないので `npm install` は不要です。

### テストを走らせる

```bash
node --test
```

`npm test` でも同じです。

### ブラウザで開く

ES モジュールを使っているため、`index.html` をファイルとして直接開くと動きません。
リポジトリのルートで簡易サーバを立ててください。

```bash
python3 -m http.server 8000
```

Node しか入っていない場合は次でも構いません。

```bash
npx --yes serve .
```

表示されたアドレス（`python3` の場合は <http://localhost:8000/>）をブラウザで開きます。

スマートフォンの実機で見る場合は、同じ Wi-Fi に繋いだうえで PC の LAN IP を使ってください。

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

## GitHub Pages での公開手順

このリポジトリは `main` ブランチのルートをそのまま公開する構成です。初回だけ次の設定を行います。

1. GitHub でこのリポジトリを開く
2. **Settings** → 左メニューの **Pages**
3. **Build and deployment** の **Source** で **Deploy from a branch** を選ぶ
4. **Branch** を `main`、フォルダを `/ (root)` にして **Save**
5. 1〜2分ほど待つと <https://grossular31415.github.io/Sanko-Bunken-maker/> で表示される

以降は `main` に push するだけで更新されます。

`.nojekyll` を置いているので、GitHub Pages 側で Jekyll の処理は行われません。

## テスト

`node --test` で `test/` 以下が実行されます。次を確認しています。

- SIST 02-2007 の用例（5.10 例1〜例3）を文字単位で再現できること
- 全項目あり
- 著者名なし、更新日なし（区切り記号が余らないこと）
- 全角文字や前後の空白を含む入力
- 不正な URL（スキームなし、http/https 以外、ホストなし）
- 長いタイトルと長い URL を切り詰めないこと
- 連名の整形、「ほか」での省略、日付の各表記

`.github/workflows/test.yml` で push と pull request のたびに同じテストが走ります。
